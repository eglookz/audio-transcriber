# Speaker diarization via MAI-Transcribe 2 + review polish — design

Дата: 2026-11-17. Размер: небольшая доработка (`transcribe.py`, README, тесты).
Одобрено пользователем в чате («Давай» на предложение).

## Зачем

`gpt-4o-transcribe-diarize` делит речь по спикерам, но:
- дороже ($0.36/ч);
- слабее на русском;
- режет запись на 15-минутные куски, метки в каждом назначаются заново.

У `microsoft/mai-transcribe-2` диаризация есть через OpenRouter за ту же цену ($0.10/ч). Проверено:
- 3-минутный диалог: реплики и короткие «угу» отнесены верно;
- 40-минутная консультация одним запросом: 20 с, $0.07, два спикера, роли не путаются по всей записи.

## Цели

- Флаг `--diarize`: включает разделение по спикерам у модели, которая его поддерживает
  (сейчас `mai`).
- Запись уходит одним запросом, пока помещается: целевой кусок 4800 с, жёсткий предел
  6000 с, 32 кбит/с (≈24 МБ < 25 МБ). Метки спикеров сквозные; для записей длиннее
  остаётся существующее предупреждение о несквозных метках.
- Имена: `--speakers 0=Мама,1=Консультант` (метки MAI — числа с 0).
- 8 мелочей из финального ревью прошлой ветки (список ниже).

## Не цели

- Диаризация Voxtral / Scribe / Deepgram (у каждого свои provider options).
- Автоматическое определение ролей по содержанию.

## Подходы

- **A. Флаг `--diarize` + `diarize_options` у модели** — *выбран*: включается явно,
  остальные режимы не меняются.
- **B. Отдельный алиас `mai-diarize`** — отклонён: модель одна, режим один флаг;
  алиас дублировал бы цену/описание.
- **C. Диаризация всегда для MAI** — отклонён: вывод становится диалогом, это меняет
  привычный `.txt`.

## Как устроено

**Транспорт (проверено).** SDK в multipart молча теряет вложенный `extra_body`. Работает
`extra_body={"provider": json.dumps({"options": {"azure": {"diarization": {"enabled": true}}}})}`.
Ответ содержит `segments[].speaker` как `int` (0, 1).

**Спек.**
- `ModelSpec.diarize_options: dict | None` — у MAI `{"azure": {"diarization": {"enabled": True}}}`.
- `--diarize` в `parse_args`: если у модели нет ни `diarize_options`, ни `diarizes` — `parser.error`.
  Иначе в `MODEL_SPECS[model]` кладётся `dataclasses.replace(spec, diarizes=True,
  default_chunk_seconds=4800, max_seconds=6000)` и `args.diarize=True`.
- Для `gpt-4o-transcribe-diarize` флаг ничего не меняет.

**Запрос.** При `args.diarize` и `spec.diarize_options` в `transcribe_chunk` добавляется
`extra_body` (см. транспорт).

**Кэш.** Подпись запроса включает режим диаризации. Иначе короткая запись (один кусок
с тем же отрезком) подхватила бы ответ без спикеров.

**Метка 0.** `payload_segments` и `render_srt` проверяют `speaker is not None`, а не
истинность.

## 8 мелочей

1. `MissingKeyError` для openrouter: если задан `OPENAI_API_KEY`, подсказать `--model whisper-1`.
2. В `chunk_dir` есть кэш `*.json` с другой подписью — сказать, сколько, и что тот же
   `--model`/`--language` переиспользует их.
3. 402 — текст «баланс или лимит ключа OpenRouter (OpenAI) исчерпан», без имени модели.
   403 — с `api_message`.
4. 402 in-flight не тратит обычные попытки: отдельный лимит ожиданий (10). Если исчерпан —
   ошибка с советом `--workers 1`.
5. Опечатка в имени без `/` — подсказка похожих из алиасов и встроенных моделей.
6. Проверка каталога: ловит любой `Exception` (это необязательный шаг) → предупреждение.
7. README и `--help`:
   - пример стоимости;
   - `--workers 1` — контекст только для моделей OpenAI;
   - раздел про диаризацию через `--diarize`.
8. Тесты: autouse-фикстура сохраняет/восстанавливает `MODEL_SPECS`.
