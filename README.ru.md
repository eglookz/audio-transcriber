# audio-transcriber

Транскрипция длинных аудиозаписей (1–3 часа и больше, диктофон Android и т.п.) в текст
через OpenAI Audio API.

*Read in English: [README.md](README.md)*

API принимает файлы не больше 25 МБ, поэтому запись автоматически:

1. измеряется (`ffprobe`),
2. сканируется на паузы (`ffmpeg silencedetect`),
3. режется на куски **по паузам**, чтобы не рвать слова посередине,
4. транскрибируется кусками — параллельно, с ретраями и кэшем на диске,
5. склеивается обратно в готовые файлы.

## Установка (один раз)

```powershell
# 1. FFmpeg (если ещё нет)
winget install Gyan.FFmpeg

# 2. Python-зависимости
pip install -r requirements.txt

# 3. API-ключ: скопировать .env.example в .env и вставить ключ
copy .env.example .env
```

Ключ можно задать и через переменную окружения вместо `.env`:

```powershell
$env:OPENAI_API_KEY = "sk-proj-..."          # только на текущую сессию
setx OPENAI_API_KEY "sk-proj-..."            # навсегда (нужен новый терминал)
```

## Использование

Положить записи в папку `input/` и запустить:

```powershell
python transcribe.py
```

Или двойным щелчком по `run.bat` (он же принимает файлы drag-and-drop).

По ходу работы видно, что происходит и сколько осталось — на каждом этапе свой
прогресс-бар с ETA:

```text
>> [1/2] Recording_2026-07-28.m4a  (2:47:13, 96.4 MB, ~$1.00)
   scan pauses  [████████████████████████] 100% 812 pauses | took 0:41
   812 pauses found -> 12 chunks of ~0:13:56
   cut chunks   [██████████░░░░░░░░░░░░░░]  41% 5/12 | ETA 1:12
   transcribe   [██████████████░░░░░░░░░░]  58% 7/12 chunks | ETA 2:35
```

Результат появляется в `output/` — на каждую запись три файла:

| Файл                  | Что внутри                                         |
| --------------------- | -------------------------------------------------- |
| `имя.txt`             | чистый текст, разбитый на абзацы по паузам         |
| `имя.timestamped.txt` | тот же текст с метками `[0:02:00]` каждые 2 минуты |
| `имя.srt`             | субтитры с точными таймкодами                      |

### Частые варианты запуска

```powershell
python transcribe.py record.m4a                  # один файл (можно путь или имя из input/)
python transcribe.py D:\Recordings               # всю папку
python transcribe.py --dry-run                   # показать план нарезки, ничего не тратя
python transcribe.py --language en               # английский
python transcribe.py --language auto             # автоопределение языка
python transcribe.py --workers 8                 # быстрее (8 параллельных запросов)
python transcribe.py --workers 1                 # медленнее, но с контекстом между кусками
python transcribe.py --force                     # перезаписать готовый результат
python transcribe.py --list-models               # какие есть модели и что умеют
python transcribe.py --model gpt-transcribe      # самый точный текст (без таймкодов)
python transcribe.py --model gpt-4o-transcribe-diarize       # разметить, кто говорит
python transcribe.py --prompt "Kubernetes, CI/CD, Grafana"   # подсказка по именам и терминам
```

### Все параметры

| Параметр        | По умолчанию | Назначение                                                           |
| --------------- | ------------ | -------------------------------------------------------------------- |
| `--model`       | `whisper-1`  | какая модель распознаёт речь — см. таблицу ниже                      |
| `--list-models` | —            | показать возможности всех моделей и выйти                            |
| `--language`    | `ru`         | код языка ISO-639-1 или `auto`                                       |
| `--prompt`      | —            | имена, термины, написание — заметно повышает точность                |
| `--speakers`    | —            | переименовать метки спикеров: `A=Денис,B=Клиент` (только диаризация) |
| `--chunk`       | `900`        | целевая длина куска в секундах                                       |
| `--workers`     | `4`          | число параллельных запросов (`1` — последовательно, с контекстом)    |
| `--input-dir`   | `./input`    | откуда брать записи                                                  |
| `--output-dir`  | `./output`   | куда писать текст                                                    |
| `--work-dir`    | `./work`     | временные куски и кэш                                                |
| `--force`       | —            | перетранскрибировать, даже если результат уже есть                   |
| `--keep-work`   | —            | не удалять куски и кэш после успеха                                  |
| `--dry-run`     | —            | только план нарезки, без запросов к API                              |
| `--no-progress` | —            | без прогресс-баров, только обычные строки лога                       |

## Устойчивость к сбоям

Каждый кусок сохраняется в `work/<имя>/chunks/` сразу после ответа API.
Если процесс упал, интернет отвалился или вы нажали Ctrl+C — просто запустите команду
снова: готовые куски берутся из кэша, деньги за них второй раз не списываются.
После успешной сборки `work/<имя>/` удаляется (отключается флагом `--keep-work`).

Кэш привязан к тому, что именно в нём лежит: имя файла содержит точные границы
отрезка, параметры кодирования и отпечаток запроса (модель, язык, промпт). Поэтому
при смене `--chunk` или модели старый результат не может подставиться под новый
отрезок — он просто не найдётся, а лишние аудиокуски прошлой нарезки удаляются
(их восстановление бесплатно). Совпадающие куски по-прежнему берутся из кэша.

Уже транскрибированные записи пропускаются: если `output/имя.txt` существует, файл
не обрабатывается повторно без `--force`.

Ошибки API скрипт различает по смыслу:

- **временные** (настоящий rate limit `429`, `500`, обрыв связи) — повтор с растущей
  задержкой, с уважением заголовка `Retry-After`;
- **неподдерживаемый параметр** (`400`) — параметр снимается, запрос повторяется;
- **безнадёжные** — кончился баланс (`insufficient_quota`), неверный ключ (`401`),
  нет доступа к модели (`404`): повторы бессмысленны, поэтому скрипт сразу
  останавливается с объяснением, что делать, и не гоняет остальные куски.
  Неудачные запросы не тарифицируются.

## Сколько это стоит и сколько ждать

- `whisper-1` — **$0.006 за минуту** аудио: час ≈ $0.36, три часа ≈ $1.08.
  `gpt-transcribe` дешевле — $0.0045/мин, три часа ≈ $0.81.
  Скрипт печатает оценку для выбранной модели перед запуском.
- Время: при `--workers 4` три часа записи обрабатываются примерно за 5–10 минут.

## Выбор модели

Сравнить прямо из скрипта: `python transcribe.py --list-models`

| Модель                              | Таймкоды | Спикеры | `--prompt` | $/мин   |
| ----------------------------------- | -------- | ------- | ---------- | ------- |
| `whisper-1` (по умолчанию)          | да       | нет     | да         | $0.006  |
| `gpt-transcribe`                    | нет      | нет     | да         | $0.0045 |
| `gpt-4o-transcribe`                 | нет      | нет     | да         | $0.006  |
| `gpt-4o-mini-transcribe`            | нет      | нет     | да         | $0.003  |
| `gpt-4o-mini-transcribe-2025-12-15` | нет      | нет     | да         | $0.003  |
| `gpt-4o-transcribe-diarize`         | да       | да      | нет        | $0.006  |

Что это значит на практике:

- **`whisper-1`** — Whisper V2. Единственная модель, отдающая таймкоды для каждого
  фрагмента, поэтому `.srt` и `.timestamped.txt` получаются только с ней.
  Значение по умолчанию.
- **`gpt-transcribe`** — самая новая и самая точная модель для файлов, при этом дешевле
  Whisper. Таймкодов не отдаёт: на выходе будет один `.txt`. Берите её, если нужен
  максимально точный текст и не нужны субтитры.
- **`gpt-4o-transcribe`** — предыдущее поколение, `gpt-transcribe` её заменяет.
- **`gpt-4o-mini-transcribe`** — самая дешёвая, чуть менее точная. Версия с датой —
  зафиксированный снапшот (не «поедет» при обновлении модели).
- **`gpt-4o-transcribe-diarize`** — размечает, **кто** что сказал (см. ниже).
  Не принимает `--prompt` — ограничение API, скрипт предупредит и проигнорирует его.
  Плюс жёсткий лимит 1400 секунд аудио на запрос, который скрипт учитывает при нарезке.

Цены — с [прайса OpenAI](https://developers.openai.com/api/docs/pricing),
сверены 30.07.2026.

Скрипт не полагается на эту таблицу жёстко: если API сообщит, что какой-то параметр
для выбранной модели не поддерживается, скрипт снимет его и повторит запрос, а не
упадёт на каждом куске. Это важно, потому что набор моделей у OpenAI меняется быстрее,
чем версии SDK.

### Что выбрать для русской речи

Русский поддерживают все модели из таблицы, и указание `--language ru` (значение по
умолчанию) заметно помогает точности и скорости на всех.

- Нужен **самый точный текст** — `--model gpt-transcribe`. Плюс дешевле Whisper.
- Нужны **таймкоды или субтитры** — `--model whisper-1` (по умолчанию). У Whisper
  точность на русском ниже, чем у GPT-моделей, но только он даёт `.srt`.
- Нужно **кто говорит** — `--model gpt-4o-transcribe-diarize`.
- Нужно **дёшево на больших объёмах** — `--model gpt-4o-mini-transcribe`.

Для русских записей особенно помогает `--prompt` со списком имён, названий и терминов,
которые в них звучат: без подсказки модель пишет их на слух и по-разному в разных местах.

## Диаризация: кто говорит

Диаризация — разделение записи по голосам: модель не просто переводит речь в текст,
а помечает каждую реплику меткой говорящего. Для записи совещания или созвона на выходе
получается диалог вместо сплошной стены текста:

```powershell
python transcribe.py --model gpt-4o-transcribe-diarize
```

Спикеры по умолчанию помечаются буквами:

```text
A: Добрый день, как дела с релизом?

B: Тестируем, завтра выкатим. Осталась одна регрессия.

A: Хорошо, держите в курсе.
```

Буквы можно заменить на имена — уже после расшифровки, по факту того, кто где оказался:

```powershell
python transcribe.py --model gpt-4o-transcribe-diarize --speakers A=Денис,B=Клиент
```

**Важное ограничение.** Метки спикеров модель присваивает независимо в каждом куске,
поэтому `A` в начале записи и `A` через час — не обязательно один и тот же человек.
Скрипт из-за этого никогда не склеивает реплики через границу куска и печатает
предупреждение, если кусков больше одного. Чтобы меток было меньше и они были
согласованнее, хочется куски побольше — но у этой модели два ограничения.

Во-первых, жёсткий лимит **1400 секунд (23:20) на запрос**, не описанный в
документации: на куске в 44 минуты API отвечает `audio duration 2682.09 seconds is
longer than 1400 seconds which is the maximum for this model`. Скрипт знает про него и
не даст превысить — при `--chunk 2700` значение автоматически снизится с предупреждением.

Во-вторых, диаризация отвечает заметно медленнее остальных моделей: кусок на 20 минут
успевает упереться в таймаут запроса. Поэтому кусок для неё — 15 минут, аудио кодируется
компактнее (32 кбит/с), а таймаут поднят до 20 минут на запрос.

## Заметки по качеству

- Записи диктофона Android (`.m4a`, `.amr`, `.3gp`, `.opus`, `.wav`, …) читаются напрямую,
  конвертировать вручную не нужно — каждый кусок кодируется в моно MP3 16 кГц.
- `--prompt` со списком имён, названий и аббревиатур из записи ощутимо снижает
  число ошибок в их написании.
- `--workers 1` передаёт хвост предыдущего куска как контекст следующему: чуть более
  связный текст на стыках, но обработка идёт последовательно и дольше.
- Если запись очень тихая и нарезка получается «жёсткой» (в логе мало найденных пауз),
  помогает уменьшить `--chunk`, например `--chunk 600`.
